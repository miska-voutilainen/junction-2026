# Development

<!-- From clone to running in five minutes. Kept current by docs-keeper. -->

## Prerequisites

- Node 24 or newer and pnpm 12.11.2 (set by `packageManager` in `package.json`).
- Git, for `pnpm seed` and the receipt CLI. The receipt CLI also needs `ssh-keygen`.
- Docker, only on the laptop that runs the pipeline: step A5 runs `dotnet restore` and `dotnet test` on the fork in temporary worktrees inside the pinned .NET SDK 8.0 image (the limit is 15 min per run; the first run pulls the image and fills the NuGet volume `countersign-a5-nuget`). The host needs no .NET SDK. Without Docker, `pnpm review run` stops with "Docker is not running. Start Docker Desktop, or run with --no-tests." Not needed to run the site.

## Setup

1. Clone the repository.
2. Install dependencies: `pnpm install --frozen-lockfile`
3. Copy `.env.example` to `.env` and fill in the values (never commit `.env`). The names are `AI_BACKEND`, `ANTHROPIC_API_KEY`, `KIMI_API_KEY`, `SAMPLE_REPO_DIR`, `AI_MODE` and `ACCESS_CODE`; the table below says what each is for. The app alone (`pnpm dev`) needs none of them: it reads the committed files under `data/`.
4. Clone the fork: set `SAMPLE_REPO_DIR` in `.env` to an absolute path, then run `pnpm seed`. It clones `miska-voutilainen/junction26-messagepack-csharp` (our fork of Tieto's repository) into that folder, fetches every branch and the receipt notes, and checks that the head commit of each sample change is there. Only the pipeline and the receipt CLI read the clone.
5. Start: `pnpm dev`, then open <http://localhost:3000> (`PORT` overrides).

## Testing

- **Unit:** `pnpm test` runs Vitest in jsdom over `src/**/*.test.ts(x)` and `scripts/**/*.test.ts`. Tests sit next to the code (`route.ts` and `route.test.ts`).
- **End to end:** `pnpm e2e` runs the specs in `e2e/` with Playwright at 1440x900 (`desktop`) and 375x812 (`mobile`). Unless `E2E_BASE_URL` is set, it runs `pnpm build && pnpm start` on `PORT` (default 3000) first. The `desktop` and `mobile` projects run on fixture data: the server is built with `COUNTERSIGN_DATA_ROOT` pointing at a copy of `data/fixtures` (made in `.review/e2e-data-root`), so they stay the same while recordings land. The `real-data` project (`e2e/real-data.spec.ts`) runs against `data/` as committed on a second server at `PORT` + 1, built into `node_modules/.cache/next-real-data`; it reads its expectations from `data/` and checks that the inbox lists only the Tieto changes. Pages are generated at build time, so a server already running on either port is reused with whatever data it was built with: stop it before changing data or env. To test a preview or production, set `E2E_BASE_URL=<url>`. If `ACCESS_CODE` is set, the specs unlock the gate with it (`e2e/unlock.ts`).
- **Legacy guard:** the security promise Tieto cares most about (idea 9) has two kinds of unit test, all with no model call and no git.
  - **Detector examples** check that each kind of touch is found or skipped on hand-written hunks, against a fake base commit that stands in for git:
    - [`legacyTouchPoints.test.ts`](../src/pipeline/legacyTouchPoints.test.ts): zones, reach-ins, old-platform `#if`, consumer contracts, build files and their guards.
    - [`csharpSymbols.test.ts`](../src/pipeline/csharpSymbols.test.ts): calls and declarations, never text inside strings, comments or T4 template output.
    - [`addLegacyGuard.test.ts`](../src/pipeline/addLegacyGuard.test.ts): R8 refusals, their ids, re-runs.
    - [`legacy.test.ts`](../src/policy/legacy.test.ts): the zone map.
  - **Invariants** in [`legacyGuardInvariants.test.ts`](../src/rules/legacyGuardInvariants.test.ts) run over every recorded `data/runs/*/review.json`: no claim or ladder level takes an R8 hunk off the reading list, an unguarded touch always routes Full, each hunk has one reader, `addLegacyGuard` is idempotent, and the guard never lowers the tier. A newly recorded review is covered as soon as it lands in `data/runs/`.
  - Run only these with `pnpm vitest run legacy csharpSymbols`. Still open: adversarial inputs that try to make a detector miss a touch (#236) and the e2e checks of the guard on S2 and S4 (#238).
- **Harness hooks:** `pnpm test:hooks` runs the `node --test` suites in `.claude/hooks/`.
- **Evals:** `pnpm evals` is the planted-bug eval. It calls the model and costs credits. `--runs <n>` (default 2) sets the anchored and blind runs per contradiction plant; runs already in `data/runs/` for the current reviewer version are reused, so `--runs 2` then `--runs 3` only records the third (the committed report card stopped at 2: [decisions](decisions.md)). `--check` is what CI runs: it re-scores the runs on disk, writes nothing and fails when `data/eval/report-card.json` does not match (fix: `pnpm evals --score-only`, commit `data/eval/` and `data/runs/`). `--score-only` makes no model call: it scores the runs on disk. Either way it writes `data/eval/report-card.json`, routes the four Tieto reviews again with the measured levels and adds the anchored-versus-blind result to `docs/lessons.md`. Code: `src/pipeline/eval/`.

## CI

`.github/workflows/ci.yml` runs on every pull request and every push to `main`, as one job in this order: message check (no emoji or AI trailer in the title, body or commits), lane check (the PR touches only its author's lanes, or carries `cross-lane`), tree check, hook and CI-script tests, lint, typecheck, unit tests, build, gitleaks. The scripts are in `.github/scripts/`; run one locally with its env vars, for example `PR_AUTHOR=Kasanen PR_LABELS='[]' node .github/scripts/checkLanes.mjs`. A PR that changes only Markdown skips lint to build. `.github/workflows/e2e-preview.yml` runs the Playwright demo path against each finished Vercel deployment; it runs only the `real-data` project against the deployed URL, and only for a commit that is the head of a branch in this repository. It needs the repository secrets `VERCEL_AUTOMATION_BYPASS_SECRET` (every deployment URL sits behind Vercel Authentication) and `ACCESS_CODE` (production only; it must mirror the value in Vercel's production env), and skips with a notice when one is missing. It is informational.

Two more workflows run Countersign's own ideas in CI. They are opt-in and cost nothing on a PR that does not ask for them (spec section 5, CI workflows):

- `countersign.yml`: a PR body line `Countersign: <changeId>`, or a manual run with `change_id`, starts `receipt` (seeds the sample fork, runs `pnpm countersign verify`, fails on any exit code but 0) and `review` (runs `pnpm review run`, then posts or updates one PR comment from `pnpm review comment`). Add `receipt` to the `protect-main` ruleset to make it a merge gate; it is not required here. The repository secret `ANTHROPIC_API_KEY` (set a spending limit on the key) makes `review` call the model; without it `review` replays the committed recordings for free, or shows the committed review where they stop short, and the comment says which. Run the pieces locally: `PR_BODY='Countersign: mp-2283' node .github/scripts/countersignChange.mjs`, `pnpm countersign verify mp-2283`, `pnpm review comment mp-2283 --receipt-exit 0`.
- `countersign-eval.yml`: runs `pnpm evals` when `src/prompts/**`, `src/policy/**` or a file the prompts import changes (or by hand), compares the new report card with the committed one with `node .github/scripts/levelDiff.mjs <before> <after>` and fails when an area's level dropped. It spends model credits and needs the same secret. Fork PRs skip both workflows' paid steps. `ci.yml` also runs `.github/scripts/checkReviewerVersion.mjs`, which fails a PR that changes `src/prompts/**` (not tests) or a file a prompt imports without changing the value of `reviewerVersion` in `src/pipeline/assembleReview.ts`; the bump is what makes `pnpm evals` re-measure the reviewer.

`main` is protected by the `protect-main` ruleset (Settings, Rules): changes land only through a squash-merged PR, `ci` must pass before the merge button works, and force pushes and deleting `main` are blocked. No approval is required, and the branch need not be up to date with `main` (several sessions merge in parallel; requiring it would re-run every open PR after each merge).

## Deploying

Vercel's Git integration deploys: every pull request gets a preview, and a merge to `main` goes to production at https://countersign-junction.com (`www` and `http` redirect to it; DNS is on Cloudflare as DNS-only records pointing at Vercel). The Vercel project is "junction-2026" in the team "junction". `vercel.json` sets the Next.js framework, `pnpm install --frozen-lockfile` and `pnpm build`.

The `*.vercel.app` preview URLs are behind Vercel Authentication; only custom domains are public. To roll back, promote an earlier deployment in the Vercel dashboard.

## Troubleshooting

- **A changed `ACCESS_CODE` has no effect on the deployed site.** Vercel applies an env change only to new deployments. Redeploy (Deployments, then Redeploy). Source: [access gate README](../src/features/access-gate/README.md).
- **`pnpm e2e` ignores a changed `ACCESS_CODE`.** Playwright reuses a server already running on the port. Stop it, then run again. Source: `playwright.config.ts`.
